Release desk note
Only events naming the requested release count. Sort by sequence, not arrival order. Replayed identical event IDs count once; conflicting copies require needs_review/review with reason conflicting_event. At equal sequence, two nonidentical events for the release are ambiguous: needs_review/review, reason ambiguous_order. A candidate event names the current build; a later candidate replaces it. Test and approval events count only for that current build and strictly after its candidate. Last test outcome for that build is authoritative. A failed test means needs_review/review, tests_failed. Missing candidate or missing test result means needs_input/request_input, missing_candidate or missing_test. Passed tests with no later approval by the release's named owner mean needs_approval/request_approval, owner_approval_missing. Passed tests plus that owner's approval mean completed/ready, ready. Owner approval must be after the latest passed test; a new test invalidates older approval. A revoke event by the owner after that approval makes approval missing again. An approval by another person never grants authority. Return current build even on missing test/approval, but null on ambiguity or no candidate. Missing request owner means needs_input/request_input, missing_owner, build null. No deployment or approval may be performed.
